## 📝 Writing Tests

### Unit Test Example

```csharp
using FluentAssertions;
using Moq;

public class YourHandlerTests
{
    [Fact]
    public async Task Handle_WithValidInput_ReturnsExpectedResult()
    {
        // Arrange
        var repositoryMock = new Mock<IYourRepository>();
        repositoryMock.Setup(r => r.GetAsync(It.IsAny<Guid>()))
            .ReturnsAsync(new YourEntity());

        var handler = new YourHandler(repositoryMock.Object);
        var command = new YourCommand { /* ... */ };

        // Act
        var result = await handler.Handle(command, CancellationToken.None);

        // Assert
        result.Should().NotBeNull();
        repositoryMock.Verify(r => r.GetAsync(It.IsAny<Guid>()), Times.Once);
    }
}
```

### Integration Test Example

```csharp
using FluentAssertions;
using System.Net;

public class YourControllerTests : IClassFixture<CustomWebApplicationFactory>
{
    private readonly HttpClient _client;

    public YourControllerTests(CustomWebApplicationFactory factory)
    {
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task GetEndpoint_ReturnsSuccess()
    {
        // Act
        var response = await _client.GetAsync("/api/your-endpoint");

        // Assert
        response.StatusCode.Should().Be(HttpStatusCode.OK);
    }
}
```

### Using AutoFixture

```csharp
using AutoFixture;
using AutoFixture.Xunit2;

public class YourTests
{
    [Theory, AutoData]
    public void Test_WithAutoGeneratedData(YourEntity entity, string name, int count)
    {
        // entity, name, count are automatically generated
        entity.Should().NotBeNull();
        name.Should().NotBeNullOrEmpty();
        count.Should().BeGreaterThan(0);
    }
}
```

### Using Bogus for Realistic Data

```csharp
using Bogus;

public class ProductTestDataGenerator
{
    public static Product CreateFakeProduct()
    {
        var faker = new Faker<Product>()
            .RuleFor(p => p.Name, f => f.Commerce.ProductName())
            .RuleFor(p => p.Price, f => f.Random.Decimal(1, 1000))
            .RuleFor(p => p.UnitsInStock, f => f.Random.Int(0, 100));

        return faker.Generate();
    }
}
```

## 🎯 Testing Best Practices

### AAA Pattern (Arrange-Act-Assert)

```csharp
[Fact]
public void Test_Example()
{
    // Arrange - Setup test data and mocks
    var mock = new Mock<IDependency>();
    var sut = new SystemUnderTest(mock.Object);

    // Act - Execute the code being tested
    var result = sut.DoSomething();

    // Assert - Verify the results
    result.Should().Be(expected);
}
```

### Test Naming Convention

- **Method_Scenario_ExpectedResult**: `Handle_WithInvalidId_ThrowsNotFoundException`
- **Should_ExpectedBehavior_When_Scenario**: `Should_ReturnProduct_When_ValidIdProvided`

### Test Organization

- One test class per handler/service
- Group related tests with `Theory` and `InlineData`
- Use nested classes for test categorization

### Mocking Guidelines

- Mock external dependencies (repositories, services)
- Don't mock the class you're testing
- Verify important interactions with `Verify()`
- Use `It.IsAny<>()` for flexible matching

### FluentAssertions Tips

```csharp
// Collections
result.Should().HaveCount(5);
result.Should().Contain(x => x.Id == expectedId);
result.Should().BeEmpty();

// Objects
product.Should().NotBeNull();
product.Should().BeEquivalentTo(expectedProduct);
product.Name.Should().Be("Expected Name");

// Exceptions
Action act = () => sut.ThrowException();
act.Should().Throw<InvalidOperationException>()
   .WithMessage("Expected message");

// Async
await sut.ExecuteAsync().Should().CompleteWithinAsync(TimeSpan.FromSeconds(1));
```

## 🔧 Troubleshooting

### Tests not discovered

```bash
# Rebuild the solution
dotnet build

# Clear test cache
dotnet test --no-build
```

### Integration tests fail with database errors

- Check `CustomWebApplicationFactory` configuration
- Ensure in-memory databases are properly configured
- Verify DbContext initialization

### Mocks not working as expected

- Check mock setup is called BEFORE the method execution
- Verify the exact parameters with `It.Is<>()`
- Use `.Verifiable()` and `.VerifyAll()` to catch issues
